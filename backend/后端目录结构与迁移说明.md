# 后端目录结构与迁移说明

整理日期：2026-10-26。后端根目录为 `code/backend`，业务包为 `dataagent`。本文路径除旧路径列和明确写出的 `code/` 路径外，均相对后端根目录。

各业务仓储与 ORM 留在所属业务的 `repositories/`、`models/` 中。通用连接由 `infra/` 提供；业务 SQL、索引操作及结果映射不移入通用设施。`assistant/events.py` 集中保存本业务的内部执行活动，消息类型与外部 SSE 帧仍按原协议区分。

Analyst、Reviewer 原本通过同一个专家构建与执行实现，根据角色配置切换提示词、模型、工具和技能。继续复用 `orchestrator.py`、`agent/specialist/` 与 `agent/common/`；未为目录对称复制执行代码。Planner 原来通过流式循环驱动框架图，因此该循环进入 `planner/invoker.py`，共用图创建进入 `common/graph.py`。

`code/web/`、独立数据生成子模块 `code/dbmock/`、根 `.gitmodules` 与已有 `code/.venv/` 保持原有归属。`dbmock` 是独立仓库，非后端应用包；开发工具通过 `ROOT_DIR.parent / "dbmock"` 找到它。根 Makefile 负责前后端统一启动。前端仅 `package.json` 中两个后端协议工具命令更新了目录，没有修改前端业务源码或生成的接口类型。

## 路径与运行方式

| 内容 | 新定位与保持的约定 |
|---|---|
| 配置 | `dataagent/engines/contract/config.py` 计算后端根目录，加载 `backend/conf/app_config.yaml` 与 `backend/conf/.env`；配置键、值和环境变量名称未改 |
| 提示词 | `dataagent/engines/prompts/`；`load_prompt()` 的 `agents/planner` 等调用参数不变，文件内容不变 |
| 技能 | `backend/resources/skills/`；只读挂载仍为 `/skills/analyst/` |
| 日志 | 继续输出 `code/logs/`，未改到另一运行目录 |
| 沙箱产物 | 原 Docker 卷、用户、Conversation、Session 路径与命名全部保持 |
| Celery | 仅 include 模块路径迁移到 `dataagent.app.workers.*`；14 个显式任务名、队列、路由和 Beat 周期不变 |
| Beat 本地状态 | `--schedule ../celerybeat-schedule` 保持原 `code/celerybeat-schedule` 位置 |
| 依赖与环境 | `backend/pyproject.toml`、`uv.lock` 和 `.python-version`；依赖声明和锁文件未改，已有 `code/.venv` 未移动或重建 |
| 后端工具 | `backend/scripts/`；OpenAPI 工具加载 `dataagent.app.app` 并输出 `code/web/src/api/generated.ts`；元数据工具读取 `code/dbmock/scripts/sql/ecommerce.sql` |
| Docker | `backend/docker/` 整体迁移，Compose 相对 build/挂载关系与命名卷名保持原样 |

在 `code/backend` 使用现有环境，PowerShell 示例：

```powershell
$env:UV_PROJECT_ENVIRONMENT = Join-Path (Split-Path (Get-Location).Path) ".venv"
$env:PYTHONUTF8 = "1"
uv run python -m dataagent.main
uv run celery --app dataagent.engines.common.tasks.celery_app:celery_app worker -l INFO
uv run celery --app dataagent.engines.common.tasks.celery_app:celery_app beat -l INFO --schedule ../celerybeat-schedule
```

已有环境也可直接使用 `../.venv/Scripts/python.exe -m dataagent.main`（Windows）。Linux/WSL 使用已有环境的 `../.venv/bin/python`。配置仍需按 README 准备，未创建或覆盖本地 `.env`。
